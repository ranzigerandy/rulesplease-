Feasibility report

Een rules chatbot kan werken, maar alleen met gecontroleerde bronnen en page-aware retrieval.

Dit browserrapport vat de research samen over BGG, rulebook discovery, PDF parsing, retrieval, modelkeuze, kosten en MVP-scope.

Executive Summary

MVP: Go Niet als volledig automatische long-tail oplossing, wel als gecontroleerde workflow met review en citaties.
BGG: dependency API-gebruik vereist registratie, approval, bearer token en mogelijk commerciele licentie.
OCR verplicht Een test-PDF voor Viticulture had 20 pagina's maar 0 extraheerbare tekst zonder OCR.

Aanbevolen MVP-route

  • BGG alleen gebruiken voor spelidentificatie.
  • Publisher-first rulebook discovery met manual review bij twijfel.
  • PDF opslaan als bron, maar indexeren op pagina- en chunkniveau.
  • Hybrid retrieval: full-text plus vector search plus reranking.
  • Antwoorden alleen uit geciteerde passages met paginanummer.

Belangrijkste blokkades

  • BGG approval en commerciele voorwaarden.
  • Juridische toestemming voor bewaren/verwerken van rulebooks.
  • Foutieve editie of expansion-rulebook.
  • PDF's met image-only tekst of complexe layouts.
  • Hallucinaties zonder harde retrieval-gate.

BGG API En Spelidentificatie

Go with dependency

BGG XML API2 documenteert /xmlapi2/search voor naamzoekopdrachten en /xmlapi2/thing voor detailmetadata. De actuele "Using the XML API" pagina vermeldt registratie, approval, authorization en bearer tokens. Een applicatie moet server-side cachen en requestvolumes beperken.

GET https://boardgamegeek.com/xmlapi2/search?query=wingspan&type=boardgame&exact=1
Result: 401 Unauthorized

GET https://boardgamegeek.com/xmlapi2/thing?id=266192&stats=1
Result: 401 Unauthorized

UX-conclusie

  1. User typt spelnaam.
  2. Backend zoekt BGG server-side met token.
  3. UI toont kandidaten met titel, jaar, type, publisher en eventueel image/rating.
  4. User kiest exact spel.
  5. bgg_game_id wordt de primaire identity voor rulebook discovery.

Discovery pipeline

Bronvolgorde

  1. Official publisher page uit BGG metadata of web search.
  2. Publisher domain search.
  3. Generic web search op titel plus rulebook PDF.
  4. BGG files alleen als discoverability signal.
  5. Retail/library mirrors alleen als fallback.
  6. Manual review bij lage confidence.

Ranking-signalen

  • Publisher domain match.
  • PDF filename bevat titel of afkorting.
  • Tekst bevat titel, publisher, setup/components.
  • BGG year/publisher match.
  • Geen expansion-keywords tenzij expliciet gekozen.
  • PDF is tekst-extractable of OCRbaar.

PDF Parsing En Opslag

Go met OCR

De PDF-pipeline moet bronbestanden, pagina's, tekst en chunks apart bewaren. Alleen een PDF blob opslaan is onvoldoende voor betrouwbare citaties.

Opslagmodel

  • games: BGG id, titel, jaar, publisher, editie.
  • rulebook_sources: URL, source type, confidence, legal status.
  • rulebooks: file hash, storage key, size, page count, status.
  • rulebook_pages: page number, extracted text, OCR flag.
  • rulebook_chunks: chunk text, page range, heading, confidence.
  • chunk_embeddings: vector, model, dimensions.

Indexing

  • Full-text index op page/chunk text.
  • Trigram of exacte keyword search voor kaartnamen en regeltermen.
  • Vector index voor semantische retrieval.
  • Metadata filters op BGG id, taal, editie en expansion-status.

Retrieval En Chatbotarchitectuur

Regex alleen is te smal en vector search alleen is te los. De juiste default is hybrid retrieval met een harde bewijsdrempel.

  1. Normalize question.
  2. Detect selected game and rulebook edition from session.
  3. Run exact/full-text retrieval.
  4. Run vector retrieval.
  5. Merge and rerank results.
  6. Keep top 4-8 chunks with page numbers.
  7. Generate answer only from supplied chunks.
  8. Require structured output: answer, citations, confidence, not-found flag.
  9. If no chunk passes threshold, answer that the rule is not found in the loaded rules.
  10. UI opens the cited PDF page with "Bekijk passage".
You are a rules assistant. Answer only from the provided rule passages.
If the passages do not contain the answer, say that the answer is not found in the loaded rules.
Every factual claim must cite at least one passage id and page number.
Do not use general board game knowledge.

DeepSeek Vs OpenAI

DeepSeek

Goed kandidaat-answer-model na retrieval. De docs tonen OpenAI-compatible API's en lage tokenprijzen. Het is geen vervanging voor retrieval, OCR, page metadata of citation checks. Er werd geen first-party embeddings/file-search equivalent gevonden zoals OpenAI File Search.

Beste rol: kostenoptimisatie na een citation-eval suite.

OpenAI

Sterker voor een end-to-end prototype dankzij File Search en Vector Stores. Voor productie blijft self-managed retrieval aanbevolen door de nood aan deterministische paginacitaties, source confidence en legal metadata.

Beste rol: prototype en eerste MVP wanneer citation quality prioritair is.

Go/No-Go En Risico's

BGG game search Go with dependency Technisch simpel, maar afhankelijk van approval, token en licentie.
Rulebook discovery Go for MVP Werkt voor testcases, maar niet volledig automatisch voor long-tail.
PDF parsing Go met OCR 3/4 kandidaten hadden tekst; 1/4 vereist OCR.
Page citations Go self-managed Betrouwbaar als chunks page metadata bewaren.
DeepSeek-only No-go Goed answer model, maar geen volledige retrieval/citation oplossing.
OpenAI File Search only Prototype go Snel te valideren, maar minder controle over legal/source/page pipeline.

  • Base games only.
  • Engelstalige rulebooks.
  • Publisher source preferred.
  • Manual review bij lage confidence.
  • Self-managed ingestion en retrieval.
  • Alleen antwoorden met pagina-citaties.
